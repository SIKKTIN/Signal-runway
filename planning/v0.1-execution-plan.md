# 信号跑道 v0.1 双人开发与交付计划

本计划将现有单关卡跑酷方案落实为可在 Godot 编辑器内启动的 v0.1.0。制作人承担程序、关卡、共享接口、集成和最终验收；主美承担视觉、动画、UI 皮肤、音效及独立检查。两人沿依赖完成所有必需功能后统一交付完整版本。交付包含源工程、资源、运行说明和验证记录；不设置可执行文件打包或平台发布任务。

## 版本范围

| 内容 | v0.1 必须交付 |
| --- | --- |
| 内容与流程 | 开始界面，一条四段首关，暂停与继续，返回开始界面，结算与再次挑战 |
| 玩家控制 | 左右加减速，空中修正，可变高度跳跃，离地补跳，输入缓冲，墙面滑落与蹬墙 |
| 判定与恢复 | 静态平台与墙面，尖刺与坠落死亡，快速回到关卡起点，唯一终点判定 |
| 成绩 | 当前挑战用时、死亡次数、会话内最佳通关成绩；统一计时口径 |
| 表现 | 信号跑道风格的角色、平台、危险、终点、背景、UI、动作反馈，以及五类短音效 |
| 开发与交付 | 移动测试房、同一版本的主路径验证、主美独立检查、缺陷修复、工程内运行说明 |

首关一次无死亡通关的目标为 45–90 秒，需要实际跑通后调整。v0.1 保留 PC 键盘和单角色，资源精度以运动中清楚易辨为准。后续内容包括手柄、多关卡、收集物、成长、排行榜、长期成绩保存和中途存档点；它们不进入本次必需任务。

## 操作和挑战规则

| 输入 | 行为 |
| --- | --- |
| A 或左箭头，D 或右箭头 | 左右移动；两边同时按下视为无方向 |
| Space，W 或上箭头 | 跳跃；松开缩短上升段；长按不会落地自动连跳 |
| R | 重新开始一次完整挑战，清零当前用时与死亡数，保留会话最佳成绩 |
| Esc | 进行中进入暂停，暂停中继续；界面同时提供继续、重开、返回开始 |
| Enter 或界面按钮 | 从开始界面进入首关，或在结算后再次挑战 |

一次挑战从起点第一次有效移动或跳跃输入开始计时，到终点停止。死亡次数只在确认死亡时增加一次，死亡重生保留用时与死亡数，恢复等待也计入用时；死亡到重新可操作的目标不超过 0.8 秒。暂停、开始界面、等待首个输入和结算均不计时。R 和结算后再玩开始新的挑战，清零本轮统计；返回开始界面放弃当前挑战。

最佳成绩仅在通关时更新，以总用时更短优先，用时相同按死亡更少优先，只在本次程序会话内保存。界面标注“本轮用时包含死亡恢复时间”。死亡与终点同一物理帧触发时优先死亡；已死亡或结算后不能再触发完成或重复统计。

空中只允许沿同侧墙面蹬跳一次，落地或接触另一侧墙面后恢复该侧机会，避免原地无限攀同侧墙。墙面下滑只在空中接触有效墙且按向该墙时生效。主路径必须能依靠这套规则通过，不以调大跳高掩盖关卡问题。

## 程序和资源接口

制作人维护 project.godot、scenes/main、scenes/player、scenes/test_room、scenes/levels、scripts/core、scripts/player、scripts/level、scripts/ui。主美维护 assets/visual、assets/audio、scenes/visual、scenes/ui/skins、scripts/visual、docs/art。主美制作皮肤与独立预览场景，制作人维护 scenes/ui/logic 和界面业务脚本，并接线到主入口，避免同时编辑同一界面场景。

公共接口由制作人实现：玩家输出 state_changed(state)、action_triggered(action)、died(reason, position)，提供 reset_at(spawn_position) 和 set_control_enabled(enabled)。关卡输出 goal_reached(player)，流程控制器产生 run_started、run_restarted、stats_changed(elapsed_seconds, deaths)、run_finished(elapsed_seconds, deaths, best_seconds)、pause_changed(paused)。关卡发出完成事件，玩家只负责自身运动与死亡；表现层订阅公开事件，不修改速度、碰撞和成绩。

运动状态使用 idle、run、rise、fall、wall_slide、dead；一次性动作使用 jump、wall_jump、land、death、finish。落地音效仅由一次 land 事件触发，不能按帧重复。缺少可选粒子时保留基础反馈；必需视觉和音效必须在最终集成中就位。

参考逻辑画布 960×540，窗口初始 1280×720，界面安全边距 24 px。世界单位按 1 px 对应一个 Godot 2D 单位；角色视觉基准 24×32，碰撞基准 20×30，地形规划模数 32。视觉拉伸不改变碰撞。物理层暂定 1 为世界、2 为玩家、3 为危险、4 为终点；由制作人统一配置。

镜头跟随玩家，水平适度前视，限制在关卡范围内，危险和下一个落脚点应在起跳前可见；v0.1 默认关闭镜头震动。音频提供 Master 与 SFX 总线，短反馈不得延迟重生。沿用现有 Godot 工程，开工时记录本机实际引擎版本与渲染配置，并保持同一版本验证。

## 手感调参和关卡制作

初始水平速度 280 px/s、参考跳高 96 px、离地补跳 0.10 s、输入缓冲 0.12 s；加速度、减速度、重力、墙滑速度和蹬墙冲量集中为可调参数。先在移动测试房确定可靠的动作包络，再按实际最大跳距与可达高度搭平台。主路径使用明显低于动作极限的跳距与高度，高手优化路线可以靠近极限。

首关按安全教学、单项练习、组合挑战、终点冲刺顺序制作。安全教学先练走与短跳；单项练习分别教授坑洞和墙跳；组合挑战复用已教动作，不突然增加新规则；终点冲刺以清楚可见的金色终点收束。每个必经危险前留出观察和落脚空间，失败后起点提示仍可读。

参数与平台位置只在测试后调整，并把导致变化的失败案例写入记录。45–90 秒是无死亡通关目标，初学者用时和死亡数单独观察，不用人为冻结计时达到目标。

## 验证和完成条件

| 验证项 | v0.1 通过条件 |
| --- | --- |
| 启动与导航 | 打开工程直接运行主场景；开始、暂停、继续、返回、结算、重玩均有出口，无软锁 |
| 控制与碰撞 | 移动、轻点/长按跳跃、缓冲、补跳、墙滑、蹬墙可复现；无同侧无限攀墙，无穿平台 |
| 死亡与恢复 | 尖刺、坠落各触发一次死亡；连续至少 20 次恢复后仍可操作，重生不保留异常速度或输入 |
| 成绩与状态 | 暂停不计时，死亡恢复计时，手动重开清本轮统计，结算停止计时，最佳成绩仅通关更新 |
| 关卡与表现 | 四段主路径能通关；必经危险可预告，平台/危险/终点运动中可辨；五类音效不按帧堆叠 |
| 集成与记录 | 同一版本完成主路径和失败路径；无阻塞报错；报告记录运行入口、实际引擎版本、结果、缺陷与未覆盖项 |

制作人先自测各工作包，主美在集成版上独立检查；修复后按缺陷复现步骤复测。自动化可验证状态与统计，画面和音效必须实际运行检查。性能在本机记录分辨率、渲染设置及实际表现，不宣称覆盖未测试设备。

至少 3 名外部玩家的体验研究移到 v0.1 交付后，用于下一版难度与趣味性调整，不阻塞本次双人开发。v0.1 只声明已有技术和团队体验证据，不把自动检查或两名制作者体验写成外部玩家结论。

## 问题处理和交付节奏

沿已确定依赖持续完成所有工作包；常规实现选择由对应负责人处理，记录到任务说明或交付记录。无法启动、主路径无法通关、软锁、重复结算、成绩错误和必需资源缺失属于阻塞问题，必须修复后才能交付。非阻塞小问题写明位置、影响和后续建议。

出现共享接口变化时，制作人先更新接口说明，主美按新的公开事件修正表现，不各自修改同一共享文件。资源尚未接入时制作人可用占位形状完成逻辑自测；最终交付必须换为已验收的必需资源。
