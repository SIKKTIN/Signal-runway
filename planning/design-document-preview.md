## 策划案

### 《信号跑道》2D 平台跳跃跑酷｜总体策划案（原型）





#### 一、核心定位

《信号跑道》是一款面向 PC 键盘原型的 2D 横版平台跳跃跑酷游戏。玩家手动控制左右移动，通过可变高度跳跃与蹬墙维持流畅节奏，在短关卡中反复挑战更短用时。Steam 发行只是后续方向，原型阶段不以平台发布作为验收。

一句话体验承诺：看清路线、做出动作、明白失误、立刻重试。目标首关为一条预计 45–90 秒的完整路线；这个时长是设计假设，须以实际构建和试玩核验。

#### 二、目标玩家与体验支柱

- 目标玩家：喜欢短局挑战、精确操作和反复优化路线的 PC 玩家；首次接触者应能在安全区域理解移动与跳跃。

- 支柱 1：操作可靠。输入响应、空中修正、跳跃缓冲和短暂离地补跳共同降低“按了没反应”的挫败感。

- 支柱 2：失败公平。安全平台、尖刺、坠落边界和终点依靠形状与层级区分；碰撞边界必须与视觉一致。

- 支柱 3：重试顺畅。死亡后快速回到可操作状态，计时与死亡次数帮助玩家判断进步，完成后可立即再玩。

#### 三、玩家循环

进入首关 → 在安全区读懂输入 → 观察下一段落脚点与危险 → 奔跑、跳跃、蹬墙通过 → 失败则快速重试；到达终点则显示本次用时、死亡次数和会话内最佳成绩 → 再次挑战。原型先采用手动奔跑，不采用自动奔跑。

主要挑战来自路线阅读和动作时机，而非战斗或资源积累。首轮只验证一个可玩关卡，不以分数、收集物或排行榜替代核心手感。

#### 四、操作与主要规则

- 左右移动：具有加减速、松手减速和有限空中修正；具体速度与摩擦由移动测试房调参，不在策划案中宣称已达标。

- 跳跃：按住与轻点形成可辨高度；提供短暂离地补跳和提前按键缓冲。落地、起跳、上升与下降状态应能通过画面辨认。

- 墙面动作：贴墙下滑并可向外蹬墙跳。蹬墙是本轮唯一进阶能力；若试玩证明学习成本大于收益，应简化首关路线或移除。

- 失败与完成：尖刺接触或坠出边界触发单次死亡，重试从关卡起点开始；进入终点只结算一次。本轮不设置中途存档点。

- 计时与成绩：第一次有效移动或跳跃输入开始本轮计时，死亡恢复保留时间和死亡数且计入用时，暂停不计时；R 或结算后再玩清零本轮统计。最佳成绩仅通关时更新并在本次会话保存，细则见 v0.1 双人开发与交付计划。

#### 五、首关结构与节奏

首关从左到右分为四段：安全教学、单项练习、组合挑战、终点冲刺。地图条目描述段落顺序，具体平台高度、跳距与障碍间隔以可玩灰盒测试调整。

- 安全教学：平地移动、短跳和一次低风险失败，明确起点与重试结果。

- 单项练习：先单独出现坑洞和可蹬墙面，每个危险前给予观察空间与明确落脚点。

- 组合挑战：把跳跃、墙面与尖刺组合，但不让背景、特效或镜头遮蔽下一处落脚面。

- 终点冲刺：用短节奏收束关卡，终点在接近前可辨，触达后进入清楚的结算与再玩流程。

#### 六、功能、界面与反馈

功能归为四个职责：玩家运动管理水平、跳跃、墙面状态；关卡判定管理危险与终点；流程与成绩管理开始、重试、计时和结算；视听反馈依据已发生的状态显示动画、提示和音效。能力输入、状态、失败和验收以功能系统条目为准。

原型视觉采用“信号跑道”高对比几何工业风：青色角色、浅色安全顶边、珊瑚色三角尖刺、金色竖向终点、暗色背景。颜色是辅助通道，灰度和缩小预览中仍须靠轮廓识别。

参考画布 960×540；左上持续显示用时与死亡数，首次操作提示保持简短，死亡时不弹大型遮挡框；结算突出成绩与重玩入口。跳跃、蹬墙、落地、死亡、完成使用短反馈，音量与触发频率需在实际构建试听。

#### 七、原型范围与明确排除

- 必须交付：可运行主入口、移动测试房、完整首关灰盒、死亡重试、计时结算、基础视觉音效、同一构建的技术检查与真人试玩报告。

- 本阶段排除：战斗、敌人 AI、剧情、随机生成、成长、商店、联机、排行榜、多角色、中途存档点。手柄、收集物和三关内容在原型证据成立后再评估。

策划案和细分模块记录的是要求与假设；已应用文档不等于功能完成。测试房、资源、关卡和集成任务分别提交运行入口与证据，里程碑另行验收。

#### 八、初始调参与观测

初始试验值：水平最高速度 280 px/s（试验范围 180–420），参考跳高 96 px（64–144），离地补跳 0.10 s（0.05–0.18），提前按键缓冲 0.12 s（0.05–0.20），死亡到可操作间隔目标不超过 0.8 s。它们是调参起点，不是已经验证的手感。

每轮只调整少量参数，并记录构建版本。观察首次理解操作所需时间、各段死亡数、危险误判、首次通关用时、重试次数与玩家是否主动追求更短用时；自动测试只验证规则和流程，趣味性结论来自真人观察。

#### 十、验收与阶段转换

- M1：测试房中移动、不同高度跳跃、蹬墙和死亡重开可重复演示；视觉方案说明资源路径、识别规范与导入方式。

- M2：单一可玩构建完成启动→四段关卡→死亡重试/终点→结算→再玩；危险可预判、无软锁，计时和死亡数正确。

- M3：主美在已集成的同一版本执行独立技术与表现检查，制作人修复并复测后提交 v0.1 工程、入口和记录。至少 3 名外部玩家试玩作为交付后的体验研究，不阻塞 v0.1，也不以团队自测代替外部玩家结论。

v0.1 按“信号跑道 v0.1 双人开发与交付计划”完成单关卡工程内交付，不安排打包。后续是否进入正式开发依据核心体验证据、接口稳定度、内容积压及外部真人观察决定。

#### 十一、主要风险与待定决策

- 蹬墙学习成本可能打断跑酷节奏：先在测试房与首关单项练习段验证，再决定保留、简化或放弃。

- 过强惯性、碰撞与视觉不一致会让失败显得不公平：记录具体触发位置和输入，优先修正主路径。

- 危险物、背景和特效可能竞争注意力：在正常色、灰度和 50% 缩小画面及实际运动中检查。

- 快速重试与计时口径若不一致会削弱重复挑战：在集成任务中固定规则并用失败复测核对。

待定：手柄、收集物、长期成绩保存和后续关卡数量。原型首轮不为这些内容提前建立开发任务。

### 信号跑道 v0.1 双人开发与交付计划





本计划将现有单关卡跑酷方案落实为可在 Godot 编辑器内启动的 v0.1.0。制作人承担程序、关卡、共享接口、集成和最终验收；主美承担视觉、动画、UI 皮肤、音效及独立检查。两人沿依赖完成所有必需功能后统一交付完整版本。交付包含源工程、资源、运行说明和验证记录；不设置可执行文件打包或平台发布任务。

#### 版本范围

| 内容 | v0.1 必须交付 |
| --- | --- |
| 内容与流程 | 开始界面，一条四段首关，暂停与继续，返回开始界面，结算与再次挑战 |
| 玩家控制 | 左右加减速，空中修正，可变高度跳跃，离地补跳，输入缓冲，墙面滑落与蹬墙 |
| 判定与恢复 | 静态平台与墙面，尖刺与坠落死亡，快速回到关卡起点，唯一终点判定 |
| 成绩 | 当前挑战用时、死亡次数、会话内最佳通关成绩；统一计时口径 |
| 表现 | 信号跑道风格的角色、平台、危险、终点、背景、UI、动作反馈，以及五类短音效 |

首关一次无死亡通关的目标为 45–90 秒，需要实际跑通后调整。v0.1 保留 PC 键盘和单角色，资源精度以运动中清楚易辨为准。后续内容包括手柄、多关卡、收集物、成长、排行榜、长期成绩保存和中途存档点；它们不进入本次必需任务。

#### 操作和挑战规则

| 输入 | 行为 |
| --- | --- |
| A 或左箭头，D 或右箭头 | 左右移动；两边同时按下视为无方向 |
| Space，W 或上箭头 | 跳跃；松开缩短上升段；长按不会落地自动连跳 |
| R | 重新开始一次完整挑战，清零当前用时与死亡数，保留会话最佳成绩 |
| Esc | 进行中进入暂停，暂停中继续；界面同时提供继续、重开、返回开始 |
| Enter 或界面按钮 | 从开始界面进入首关，或在结算后再次挑战 |

一次挑战从起点第一次有效移动或跳跃输入开始计时，到终点停止。死亡次数只在确认死亡时增加一次，死亡重生保留用时与死亡数，恢复等待也计入用时；死亡到重新可操作的目标不超过 0.8 秒。暂停、开始界面、等待首个输入和结算均不计时。R 和结算后再玩开始新的挑战，清零本轮统计；返回开始界面放弃当前挑战。

最佳成绩仅在通关时更新，以总用时更短优先，用时相同按死亡更少优先，只在本次程序会话内保存。界面标注“本轮用时包含死亡恢复时间”。死亡与终点同一物理帧触发时优先死亡；已死亡或结算后不能再触发完成或重复统计。

空中只允许沿同侧墙面蹬跳一次，落地或接触另一侧墙面后恢复该侧机会，避免原地无限攀同侧墙。墙面下滑只在空中接触有效墙且按向该墙时生效。主路径必须能依靠这套规则通过，不以调大跳高掩盖关卡问题。

#### 程序和资源接口

制作人维护 project.godot、scenes/main、scenes/player、scenes/test_room、scenes/levels、scripts/core、scripts/player、scripts/level、scripts/ui。主美维护 assets/visual、assets/audio、scenes/visual、scenes/ui/skins、scripts/visual、docs/art。主美制作皮肤与独立预览场景，制作人维护 scenes/ui/logic 和界面业务脚本，并接线到主入口，避免同时编辑同一界面场景。

公共接口由制作人实现：玩家输出 state_changed(state)、action_triggered(action)、died(reason, position)，提供 reset_at(spawn_position) 和 set_control_enabled(enabled)。关卡输出 goal_reached(player)，流程控制器产生 run_started、run_restarted、stats_changed(elapsed_seconds, deaths)、run_finished(elapsed_seconds, deaths, best_seconds)、pause_changed(paused)。关卡发出完成事件，玩家只负责自身运动与死亡；表现层订阅公开事件，不修改速度、碰撞和成绩。

运动状态使用 idle、run、rise、fall、wall_slide、dead；一次性动作使用 jump、wall_jump、land、death、finish。落地音效仅由一次 land 事件触发，不能按帧重复。缺少可选粒子时保留基础反馈；必需视觉和音效必须在最终集成中就位。

参考逻辑画布 960×540，窗口初始 1280×720，界面安全边距 24 px。世界单位按 1 px 对应一个 Godot 2D 单位；角色视觉基准 24×32，碰撞基准 20×30，地形规划模数 32。视觉拉伸不改变碰撞。物理层暂定 1 为世界、2 为玩家、3 为危险、4 为终点；由制作人统一配置。

镜头跟随玩家，水平适度前视，限制在关卡范围内，危险和下一个落脚点应在起跳前可见；v0.1 默认关闭镜头震动。音频提供 Master 与 SFX 总线，短反馈不得延迟重生。沿用现有 Godot 工程，开工时记录本机实际引擎版本与渲染配置，并保持同一版本验证。

#### 手感调参和关卡制作

初始水平速度 280 px/s、参考跳高 96 px、离地补跳 0.10 s、输入缓冲 0.12 s；加速度、减速度、重力、墙滑速度和蹬墙冲量集中为可调参数。先在移动测试房确定可靠的动作包络，再按实际最大跳距与可达高度搭平台。主路径使用明显低于动作极限的跳距与高度，高手优化路线可以靠近极限。

首关按安全教学、单项练习、组合挑战、终点冲刺顺序制作。安全教学先练走与短跳；单项练习分别教授坑洞和墙跳；组合挑战复用已教动作，不突然增加新规则；终点冲刺以清楚可见的金色终点收束。每个必经危险前留出观察和落脚空间，失败后起点提示仍可读。

参数与平台位置只在测试后调整，并把导致变化的失败案例写入记录。45–90 秒是无死亡通关目标，初学者用时和死亡数单独观察，不用人为冻结计时达到目标。
