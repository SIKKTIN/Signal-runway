# 信号跑道 v0.2 信号崩塌追赶挑战计划

v0.2 的目标是在已有手动移动、跳跃与蹬墙上，加入从后方持续逼近的信号崩塌，让安全距离成为玩家可以争取、也会因停顿而消耗的资源。制作人负责规则、程序、关卡适配、集成与交付，主美负责追赶表现、危险提示、音效及独立检查。阶段保持双人原型开发，先复用现有首关验证这套机制。

## 当前成果与本次目标

v0.1 源工程已交付，32 项运动与流程检查通过，自动输入无传送通关约 48.62 秒；这些证据证明既有动作和主路径可运行。v0.2 的追赶数值、状态流程与体验尚未实现或测试，不能沿用 v0.1 结果宣称通过。

本版要回答三个问题：追赶是否形成持续前进的动机；流畅操作能否积累安全距离、短暂犹豫能否消耗但不立即耗尽它；现有蹬墙和观察落点所需的时间是否仍然公平。主观紧张感以实际玩家反馈判断，自动轨迹和团队运行记录只支持各自已检查的范围。

## 玩家循环与状态规则

选择追赶挑战 → 等待首次移动或跳跃 → 启动缓冲 → 一边穿越障碍一边维持安全距离 → 抵达终点或失败结算 → 一键重新挑战。

| 状态 | 计时与追赶 | 输入与出口 |
| --- | --- | --- |
| 开始界面 | 两者停止 | 选择模式并开始 |
| 等待首次动作 | 本轮用时为零，边界停在起点后方 | 首次有效移动或跳跃启动；R 重置，Esc 暂停 |
| 启动缓冲 | 本轮计时开始，缓冲倒计时，边界停止 | 角色自由操作；缓冲到期进入追赶 |
| 追赶中 | 用时与边界按有效游戏时间推进 | 手动控制；成功、失败、暂停、R 或返回 |
| 暂停 | 用时、缓冲、边界及威胁表现冻结 | 继续恢复原状态；R 新挑战，返回放弃 |
| 成功或失败结算 | 统计冻结，边界停止，角色停止操作 | R、Enter 或按钮再玩；返回开始界面 |

输入沿用 A/D、左右箭头、Space/W/上箭头、R、Esc、Enter。追赶不会替玩家移动，也不强制镜头自动向右滚动。最远进度用于结算，当前角色位置用于安全距离；玩家回退会真实缩短安全距离。

## 追赶边界与调参基线

追赶边界在世界坐标中横贯关卡有效高度，穿过地形持续前进，不受墙面阻挡；边界后的区域视为已被吞没。表现可将背景和地面画成失去信号的状态，首版不实际删除地形或改变平台碰撞。

安全距离定义为角色碰撞体左边缘减去追赶前沿横坐标。距离小于或等于零时失败；视觉前沿与判定位置必须一致。高速、回退和低帧率场景应检查越界过程，不能只依赖某一次 Area2D 重叠信号。

| 参数 | 首轮实验值 | 调整依据 |
| --- | --- | --- |
| 起点后方距离 | 640 px | 角色还未行动时不会被吞，重开位置稳定 |
| 启动缓冲 | 2.0 秒 | 从首次有效动作计起；允许建立起步节奏 |
| 追赶速度 | 260 px/s，首轮比较 250、260、270 | 参考角色最高速度 280 px/s 和真实关卡轨迹；以最终实测决定 |
| 警告等级 | 距离除以追赶速度：大于 4 秒为安全，2–4 秒为接近，不足 2 秒为紧急 | 这是原地停留时的估算余量，实际移动会改变距离；界面不承诺精确死亡倒计时 |
| 提示稳定 | 阈值切换加入少量回差 | 在边缘来回移动时不反复闪烁或重播音效 |

这些值是调参起点，不是已经验证的难度。首版采用固定推进速度，不做隐藏传送、距离强制夹紧或暗中追随玩家变速。若流畅路线能无限拉远、或正常蹬墙必然被吞，先比较速度、起点距离与关卡局部耗时，记录改动原因；变化写入实际参数清单。

## 失败优先级与完整重开

追赶挑战中，尖刺、坠落和吞没都结束整轮，不执行 v0.1 的死亡后自动回起点继续累计。失败结算保留本轮用时、最远进度和明确原因。多个失败原因同帧出现时固定按尖刺、坠落、吞没选择一个；任何失败与终点同帧出现都优先失败。一次挑战只发布一次最终结果。

R 或再次挑战要原子重置：角色位置、速度、动作缓存、镜头、边界位置、缓冲剩余、本轮计时、最远进度、警告状态与声音；进入等待首次动作，保留该模式的会话最佳。暂停中重开解除暂停并进入等待首次动作。重开不遗留已按下的跳跃缓存，声音不沿用上一轮的紧急状态。

成功以抵达原终点为准。最佳用时只在成功时更新，并按模式分别保存；失败记录不会覆盖成功最佳。模式仅在开始界面切换，局内返回会放弃本轮；两种规则不在进行中切换。原计时模式保持死亡自动重生、计时累计、死亡数与会话最佳的 v0.1 行为。

## 首关适配与机制验证

复用 13600 单位左右的现有四段路线，段落参考位置为 0–3400、3400–6800、6800–10200、10200–13600，实际终点与障碍以工程为准。保持已有跳跃和蹬墙规则，按每段最低安全距离与操作耗时决定局部调整。

| 区段 | 重点检查 |
| --- | --- |
| 起步段 | 从首次输入到边界启动的顺序清楚；起点等待安全，开始前进后追赶确实启动 |
| 单项障碍段 | 观察落脚点、短跳与第一次蹬墙所需的时间有余量 |
| 组合段 | 跳跃与蹬墙组合可以流畅通过，回退与停顿会明显消耗距离 |
| 终点段 | 紧急提示不遮挡最后落脚点；终点、吞没与结算优先级正确 |

对候选参数记录：有效用时、每段进入/离开时的安全距离、全程最低距离、失败原因、暂停次数与时间、最大前进位置。必须保存两处代表性安全平台的暂停输入轨迹：停止移动 2 秒后能通过后续正常操作继续完成；站立持续等待最终被吞。两种测试中的停止移动都不使用 Esc。

主路径使用普通输入连续通关，不通过传送、无敌、冻结边界或临时提高速度得到通过结果。定点 fixtures 可以验证碰撞和状态分支，但要单独标注用途。

## 功能系统与接口

| 所属系统 | 功能及边界 |
| --- | --- |
| 新增追赶威胁系统 | 负责边界位置、启动缓冲、安全距离和警告等级；不修改角色运动或成绩 |
| 关卡判定 | 新增吞没检测，统一提交危险和终点候选，由流程确定本帧结果 |
| 流程与成绩 | 扩展模式选择、追赶失败结算、完整重开与按模式统计；保留原计时规则 |
| 视听反馈 | 消费距离、等级、暂停和结果事件，负责崩塌、HUD、音效；不参与判定 |

建议主干新增 scripts/level/chase_controller.gd，复用 scripts/level/run_flow.gd、scripts/level/course.gd 和 scripts/ui/interface.gd。公开配置为 initial_gap、start_delay、speed；控制器提供 reset(spawn_x)、advance(active_delta, player_left_x)、set_enabled(enabled)，输出 threat_updated(front_x, gap_px, warning_level, grace_remaining)。

流程增加 mode_changed(mode)、run_failed(reason, elapsed, furthest_ratio) 与统一结果状态；模式固定为 time_trial、pursuit，原因固定为 spike、fall、caught。吞没判定将候选原因交给流程；原玩家 state_changed、action_triggered、died 保持兼容。具体 Godot 签名在 A 的接口说明中冻结，变化由制作人同步给主美。

## 验收清单

| 类别 | 必须验证 |
| --- | --- |
| 启动与时间 | 开始前不推进；首次输入启动一次；缓冲、边界和计时暂停冻结；正常图形进程时间与墙钟一致 |
| 追赶与碰撞 | 边界单调前进；回退缩短距离；停留最终被吞；真实左边缘判定；高速与低帧率越界不漏检 |
| 路线与余量 | 普通输入不传送全程可达；每段最低距离有记录；两处代表性 2 秒短停后仍可完成；既有两处蹬墙可通过 |
| 结果竞争 | 吞没/尖刺/坠落与终点同帧失败优先；同帧多原因取固定一种；重复信号只结算一次 |
| 重开与界面 | 连续 20 次失败→再玩及暂停中 R，角色、镜头、边界、缓冲、声音和统计均正确重置；无软锁 |
| 模式与成绩 | 追赶失败不更新成功最佳；两模式成绩隔离；原计时模式死亡恢复与完整通关回归通过 |
| 表现 | 正常与缩小预览的前沿/角色/落点清晰；无音效按帧堆叠；暂停、失败和退出不遗留威胁声 |

自动输入用于验证规则和路线可达；截图、实际图形运行与主美独立报告用于检查表现及高风险流程。用户试玩反馈用于判断紧张感和是否愿意重试；没有实际反馈时写明未验证，不虚构外部玩家研究或主观体验结论。

## 风险与处理

若追赶始终很远，比较候选速度及起步预算，检查普通路线的实际速度；若墙跳段必然失败，检查局部耗时与安全空间，保持既有动作规则。若提示遮挡落脚点，优先降低覆盖强度或调整 HUD。若死亡规则串入另一模式，集中统一结果仲裁与重开入口，并增加模式切换回归。

无启动、连续通关、重开、统计阻塞后可以交付技术实验；若实际玩家反馈认为追赶缺少紧张感或过于挫败，应记录并继续调整数值与路线，不能仅凭自动通关宣布玩法体验成立。
