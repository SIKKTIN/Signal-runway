# 信号跑道 策划案与工程记录

> 来源：GameCreator 正式同步的策划案内容。

## 策划案

### 《信号跑道》2D 平台跳跃跑酷｜总体策划案（原型）





#### 一、核心定位

《信号跑道》是一款面向 PC 键盘原型的 2D 横版平台跳跃跑酷游戏。玩家手动控制左右移动，通过可变高度跳跃与蹬墙维持流畅节奏，在短关卡中反复挑战更短用时。Steam 发行只是后续方向，原型阶段不以平台发布作为验收。

一句话体验承诺：看清路线、做出动作、明白失误、立刻重试。目标首关为一条预计 45–90 秒的完整路线；这个时长是设计假设，须以实际构建和试玩核验。

#### 二、目标玩家与体验支柱

- 目标玩家：喜欢短局挑战、精确操作和反复优化路线的 PC 玩家；首次接触者应能在安全区域理解移动与跳跃。

- 支柱 1：操作可靠。输入响应、空中修正、跳跃缓冲和短暂离地补跳共同降低“按了没反应”的挫败感。

- 支柱 2：失败公平。安全平台、尖刺、坠落边界和终点依靠形状与层级区分；碰撞边界必须与视觉一致。

- 支柱 3：重试顺畅。死亡后快速回到可操作状态，计时与死亡次数帮助玩家判断进步，完成后可立即再玩。

#### 三、玩家循环

进入首关 → 在安全区读懂输入 → 观察下一段落脚点与危险 → 奔跑、跳跃、蹬墙通过 → 失败则快速重试；到达终点则显示本次用时、死亡次数和会话内最佳成绩 → 再次挑战。原型先采用手动奔跑，不采用自动奔跑。

主要挑战来自路线阅读和动作时机，而非战斗或资源积累。首轮只验证一个可玩关卡，不以分数、收集物或排行榜替代核心手感。

#### 四、操作与主要规则

- 左右移动：具有加减速、松手减速和有限空中修正；具体速度与摩擦由移动测试房调参，不在策划案中宣称已达标。

- 跳跃：按住与轻点形成可辨高度；提供短暂离地补跳和提前按键缓冲。落地、起跳、上升与下降状态应能通过画面辨认。

- 墙面动作：贴墙下滑并可向外蹬墙跳。蹬墙是本轮唯一进阶能力；若试玩证明学习成本大于收益，应简化首关路线或移除。

- 失败与完成：尖刺接触或坠出边界触发单次死亡，重试从关卡起点开始；进入终点只结算一次。本轮不设置中途存档点。

- 计时与成绩：第一次有效移动或跳跃输入开始本轮计时，死亡恢复保留时间和死亡数且计入用时，暂停不计时；R 或结算后再玩清零本轮统计。最佳成绩仅通关时更新并在本次会话保存，细则见 v0.1 双人开发与交付计划。

#### 五、首关结构与节奏

首关从左到右分为四段：安全教学、单项练习、组合挑战、终点冲刺。地图条目描述段落顺序，具体平台高度、跳距与障碍间隔以可玩灰盒测试调整。

- 安全教学：平地移动、短跳和一次低风险失败，明确起点与重试结果。

- 单项练习：先单独出现坑洞和可蹬墙面，每个危险前给予观察空间与明确落脚点。

- 组合挑战：把跳跃、墙面与尖刺组合，但不让背景、特效或镜头遮蔽下一处落脚面。

- 终点冲刺：用短节奏收束关卡，终点在接近前可辨，触达后进入清楚的结算与再玩流程。

#### 六、功能、界面与反馈

功能归为四个职责：玩家运动管理水平、跳跃、墙面状态；关卡判定管理危险与终点；流程与成绩管理开始、重试、计时和结算；视听反馈依据已发生的状态显示动画、提示和音效。能力输入、状态、失败和验收以功能系统条目为准。

原型视觉采用“信号跑道”高对比几何工业风：青色角色、浅色安全顶边、珊瑚色三角尖刺、金色竖向终点、暗色背景。颜色是辅助通道，灰度和缩小预览中仍须靠轮廓识别。

参考画布 960×540；左上持续显示用时与死亡数，首次操作提示保持简短，死亡时不弹大型遮挡框；结算突出成绩与重玩入口。跳跃、蹬墙、落地、死亡、完成使用短反馈，音量与触发频率需在实际构建试听。

#### 七、原型范围与明确排除

- 必须交付：可运行主入口、移动测试房、完整首关灰盒、死亡重试、计时结算、基础视觉音效、同一构建的技术检查与真人试玩报告。

- 本阶段排除：战斗、敌人 AI、剧情、随机生成、成长、商店、联机、排行榜、多角色、中途存档点。手柄、收集物和三关内容在原型证据成立后再评估。

策划案和细分模块记录的是要求与假设；已应用文档不等于功能完成。测试房、资源、关卡和集成任务分别提交运行入口与证据，里程碑另行验收。

#### 八、初始调参与观测

初始试验值：水平最高速度 280 px/s（试验范围 180–420），参考跳高 96 px（64–144），离地补跳 0.10 s（0.05–0.18），提前按键缓冲 0.12 s（0.05–0.20），死亡到可操作间隔目标不超过 0.8 s。它们是调参起点，不是已经验证的手感。

每轮只调整少量参数，并记录构建版本。观察首次理解操作所需时间、各段死亡数、危险误判、首次通关用时、重试次数与玩家是否主动追求更短用时；自动测试只验证规则和流程，趣味性结论来自真人观察。

#### 十、验收与阶段转换

- M1：测试房中移动、不同高度跳跃、蹬墙和死亡重开可重复演示；视觉方案说明资源路径、识别规范与导入方式。

- M2：单一可玩构建完成启动→四段关卡→死亡重试/终点→结算→再玩；危险可预判、无软锁，计时和死亡数正确。

- M3：主美在已集成的同一版本执行独立技术与表现检查，制作人修复并复测后提交 v0.1 工程、入口和记录。至少 3 名外部玩家试玩作为交付后的体验研究，不阻塞 v0.1，也不以团队自测代替外部玩家结论。

v0.1 按“信号跑道 v0.1 双人开发与交付计划”完成单关卡工程内交付，不安排打包。后续是否进入正式开发依据核心体验证据、接口稳定度、内容积压及外部真人观察决定。

#### 十一、主要风险与待定决策

- 蹬墙学习成本可能打断跑酷节奏：先在测试房与首关单项练习段验证，再决定保留、简化或放弃。

- 过强惯性、碰撞与视觉不一致会让失败显得不公平：记录具体触发位置和输入，优先修正主路径。

- 危险物、背景和特效可能竞争注意力：在正常色、灰度和 50% 缩小画面及实际运动中检查。

- 快速重试与计时口径若不一致会削弱重复挑战：在集成任务中固定规则并用失败复测核对。

待定：手柄、收集物、长期成绩保存和后续关卡数量。原型首轮不为这些内容提前建立开发任务。

### 信号跑道 v0.1 双人开发与交付计划





本计划将现有单关卡跑酷方案落实为可在 Godot 编辑器内启动的 v0.1.0。制作人承担程序、关卡、共享接口、集成和最终验收；主美承担视觉、动画、UI 皮肤、音效及独立检查。两人沿依赖完成所有必需功能后统一交付完整版本。交付包含源工程、资源、运行说明和验证记录；不设置可执行文件打包或平台发布任务。

#### 版本范围

| 内容 | v0.1 必须交付 |
| --- | --- |
| 内容与流程 | 开始界面，一条四段首关，暂停与继续，返回开始界面，结算与再次挑战 |
| 玩家控制 | 左右加减速，空中修正，可变高度跳跃，离地补跳，输入缓冲，墙面滑落与蹬墙 |
| 判定与恢复 | 静态平台与墙面，尖刺与坠落死亡，快速回到关卡起点，唯一终点判定 |
| 成绩 | 当前挑战用时、死亡次数、会话内最佳通关成绩；统一计时口径 |
| 表现 | 信号跑道风格的角色、平台、危险、终点、背景、UI、动作反馈，以及五类短音效 |
| 开发与交付 | 移动测试房、同一版本的主路径验证、主美独立检查、缺陷修复、工程内运行说明 |

首关一次无死亡通关的目标为 45–90 秒，需要实际跑通后调整。v0.1 保留 PC 键盘和单角色，资源精度以运动中清楚易辨为准。后续内容包括手柄、多关卡、收集物、成长、排行榜、长期成绩保存和中途存档点；它们不进入本次必需任务。

#### 操作和挑战规则

| 输入 | 行为 |
| --- | --- |
| A 或左箭头，D 或右箭头 | 左右移动；两边同时按下视为无方向 |
| Space，W 或上箭头 | 跳跃；松开缩短上升段；长按不会落地自动连跳 |
| R | 重新开始一次完整挑战，清零当前用时与死亡数，保留会话最佳成绩 |
| Esc | 进行中进入暂停，暂停中继续；界面同时提供继续、重开、返回开始 |
| Enter 或界面按钮 | 从开始界面进入首关，或在结算后再次挑战 |

一次挑战从起点第一次有效移动或跳跃输入开始计时，到终点停止。死亡次数只在确认死亡时增加一次，死亡重生保留用时与死亡数，恢复等待也计入用时；死亡到重新可操作的目标不超过 0.8 秒。暂停、开始界面、等待首个输入和结算均不计时。R 和结算后再玩开始新的挑战，清零本轮统计；返回开始界面放弃当前挑战。

最佳成绩仅在通关时更新，以总用时更短优先，用时相同按死亡更少优先，只在本次程序会话内保存。界面标注“本轮用时包含死亡恢复时间”。死亡与终点同一物理帧触发时优先死亡；已死亡或结算后不能再触发完成或重复统计。

空中只允许沿同侧墙面蹬跳一次，落地或接触另一侧墙面后恢复该侧机会，避免原地无限攀同侧墙。墙面下滑只在空中接触有效墙且按向该墙时生效。主路径必须能依靠这套规则通过，不以调大跳高掩盖关卡问题。

#### 程序和资源接口

制作人维护 project.godot、scenes/main、scenes/player、scenes/test_room、scenes/levels、scripts/core、scripts/player、scripts/level、scripts/ui。主美维护 assets/visual、assets/audio、scenes/visual、scenes/ui/skins、scripts/visual、docs/art。主美制作皮肤与独立预览场景，制作人维护 scenes/ui/logic 和界面业务脚本，并接线到主入口，避免同时编辑同一界面场景。

公共接口由制作人实现：玩家输出 state_changed(state)、action_triggered(action)、died(reason, position)，提供 reset_at(spawn_position) 和 set_control_enabled(enabled)。关卡输出 goal_reached(player)，流程控制器产生 run_started、run_restarted、stats_changed(elapsed_seconds, deaths)、run_finished(elapsed_seconds, deaths, best_seconds)、pause_changed(paused)。关卡发出完成事件，玩家只负责自身运动与死亡；表现层订阅公开事件，不修改速度、碰撞和成绩。

运动状态使用 idle、run、rise、fall、wall_slide、dead；一次性动作使用 jump、wall_jump、land、death、finish。落地音效仅由一次 land 事件触发，不能按帧重复。缺少可选粒子时保留基础反馈；必需视觉和音效必须在最终集成中就位。

参考逻辑画布 960×540，窗口初始 1280×720，界面安全边距 24 px。世界单位按 1 px 对应一个 Godot 2D 单位；角色视觉基准 24×32，碰撞基准 20×30，地形规划模数 32。视觉拉伸不改变碰撞。物理层暂定 1 为世界、2 为玩家、3 为危险、4 为终点；由制作人统一配置。

镜头跟随玩家，水平适度前视，限制在关卡范围内，危险和下一个落脚点应在起跳前可见；v0.1 默认关闭镜头震动。音频提供 Master 与 SFX 总线，短反馈不得延迟重生。沿用现有 Godot 工程，开工时记录本机实际引擎版本与渲染配置，并保持同一版本验证。

#### 手感调参和关卡制作

初始水平速度 280 px/s、参考跳高 96 px、离地补跳 0.10 s、输入缓冲 0.12 s；加速度、减速度、重力、墙滑速度和蹬墙冲量集中为可调参数。先在移动测试房确定可靠的动作包络，再按实际最大跳距与可达高度搭平台。主路径使用明显低于动作极限的跳距与高度，高手优化路线可以靠近极限。

首关按安全教学、单项练习、组合挑战、终点冲刺顺序制作。安全教学先练走与短跳；单项练习分别教授坑洞和墙跳；组合挑战复用已教动作，不突然增加新规则；终点冲刺以清楚可见的金色终点收束。每个必经危险前留出观察和落脚空间，失败后起点提示仍可读。

参数与平台位置只在测试后调整，并把导致变化的失败案例写入记录。45–90 秒是无死亡通关目标，初学者用时和死亡数单独观察，不用人为冻结计时达到目标。

### 信号跑道 v0.2 信号崩塌追赶挑战计划





v0.2 的目标是在已有手动移动、跳跃与蹬墙上，加入从后方持续逼近的信号崩塌，让安全距离成为玩家可以争取、也会因停顿而消耗的资源。制作人负责规则、程序、关卡适配、集成与交付，主美负责追赶表现、危险提示、音效及独立检查。阶段保持双人原型开发，先复用现有首关验证这套机制。

#### 当前成果与本次目标

v0.1 源工程已交付，32 项运动与流程检查通过，自动输入无传送通关约 48.62 秒；这些证据证明既有动作和主路径可运行。v0.2 的追赶数值、状态流程与体验尚未实现或测试，不能沿用 v0.1 结果宣称通过。

本版要回答三个问题：追赶是否形成持续前进的动机；流畅操作能否积累安全距离、短暂犹豫能否消耗但不立即耗尽它；现有蹬墙和观察落点所需的时间是否仍然公平。主观紧张感以实际玩家反馈判断，自动轨迹和团队运行记录只支持各自已检查的范围。

#### 版本范围

| 内容 | v0.2 交付 |
| --- | --- |
| 核心机制 | 一条沿世界横坐标推进的追赶边界，启动缓冲、距离计算与吞没判定 |
| 操作与关卡 | 复用手动移动、跳跃、蹬墙和四段首关；按追赶预算局部调整障碍及观察空间 |
| 模式 | 主入口提供追赶挑战与原计时挑战；追赶挑战为默认入口，两种成绩独立 |
| 失败与循环 | 追赶中被吞、尖刺、坠落均结束本轮；原因、用时、最远进度与立即重开 |
| 表现 | 崩塌前沿、被吞区域、距离提示、分级警告、威胁音效与失败界面 |
| 交付 | Godot 源工程、同版本验证、主美独立检查、运行说明与资源清单 |

本次范围不包含教程扩建、空中冲刺、新关卡、无限生成、成长、收集物、联网排行榜、长期成绩保存、手柄或打包。既有计时挑战用于保留原规则与比较追赶的影响。

#### 玩家循环与状态规则

选择追赶挑战 → 等待首次移动或跳跃 → 启动缓冲 → 一边穿越障碍一边维持安全距离 → 抵达终点或失败结算 → 一键重新挑战。

| 状态 | 计时与追赶 | 输入与出口 |
| --- | --- | --- |
| 开始界面 | 两者停止 | 选择模式并开始 |
| 等待首次动作 | 本轮用时为零，边界停在起点后方 | 首次有效移动或跳跃启动；R 重置，Esc 暂停 |
| 启动缓冲 | 本轮计时开始，缓冲倒计时，边界停止 | 角色自由操作；缓冲到期进入追赶 |
| 追赶中 | 用时与边界按有效游戏时间推进 | 手动控制；成功、失败、暂停、R 或返回 |
| 暂停 | 用时、缓冲、边界及威胁表现冻结 | 继续恢复原状态；R 新挑战，返回放弃 |
| 成功或失败结算 | 统计冻结，边界停止，角色停止操作 | R、Enter 或按钮再玩；返回开始界面 |

输入沿用 A/D、左右箭头、Space/W/上箭头、R、Esc、Enter。追赶不会替玩家移动，也不强制镜头自动向右滚动。最远进度用于结算，当前角色位置用于安全距离；玩家回退会真实缩短安全距离。

#### 追赶边界与调参基线

追赶边界在世界坐标中横贯关卡有效高度，穿过地形持续前进，不受墙面阻挡；边界后的区域视为已被吞没。表现可将背景和地面画成失去信号的状态，首版不实际删除地形或改变平台碰撞。

安全距离定义为角色碰撞体左边缘减去追赶前沿横坐标。距离小于或等于零时失败；视觉前沿与判定位置必须一致。高速、回退和低帧率场景应检查越界过程，不能只依赖某一次 Area2D 重叠信号。

| 参数 | 首轮实验值 | 调整依据 |
| --- | --- | --- |
| 起点后方距离 | 640 px | 角色还未行动时不会被吞，重开位置稳定 |
| 启动缓冲 | 2.0 秒 | 从首次有效动作计起；允许建立起步节奏 |
| 追赶速度 | 260 px/s，首轮比较 250、260、270 | 参考角色最高速度 280 px/s 和真实关卡轨迹；以最终实测决定 |
| 警告等级 | 距离除以追赶速度：大于 4 秒为安全，2–4 秒为接近，不足 2 秒为紧急 | 这是原地停留时的估算余量，实际移动会改变距离；界面不承诺精确死亡倒计时 |
| 提示稳定 | 阈值切换加入少量回差 | 在边缘来回移动时不反复闪烁或重播音效 |

这些值是调参起点，不是已经验证的难度。首版采用固定推进速度，不做隐藏传送、距离强制夹紧或暗中追随玩家变速。若流畅路线能无限拉远、或正常蹬墙必然被吞，先比较速度、起点距离与关卡局部耗时，记录改动原因；变化写入实际参数清单。

#### 失败优先级与完整重开

追赶挑战中，尖刺、坠落和吞没都结束整轮，不执行 v0.1 的死亡后自动回起点继续累计。失败结算保留本轮用时、最远进度和明确原因。多个失败原因同帧出现时固定按尖刺、坠落、吞没选择一个；任何失败与终点同帧出现都优先失败。一次挑战只发布一次最终结果。

R 或再次挑战要原子重置：角色位置、速度、动作缓存、镜头、边界位置、缓冲剩余、本轮计时、最远进度、警告状态与声音；进入等待首次动作，保留该模式的会话最佳。暂停中重开解除暂停并进入等待首次动作。重开不遗留已按下的跳跃缓存，声音不沿用上一轮的紧急状态。

成功以抵达原终点为准。最佳用时只在成功时更新，并按模式分别保存；失败记录不会覆盖成功最佳。模式仅在开始界面切换，局内返回会放弃本轮；两种规则不在进行中切换。原计时模式保持死亡自动重生、计时累计、死亡数与会话最佳的 v0.1 行为。

#### 首关适配与机制验证

复用 13600 单位左右的现有四段路线，段落参考位置为 0–3400、3400–6800、6800–10200、10200–13600，实际终点与障碍以工程为准。保持已有跳跃和蹬墙规则，按每段最低安全距离与操作耗时决定局部调整。

| 区段 | 重点检查 |
| --- | --- |
| 起步段 | 从首次输入到边界启动的顺序清楚；起点等待安全，开始前进后追赶确实启动 |
| 单项障碍段 | 观察落脚点、短跳与第一次蹬墙所需的时间有余量 |
| 组合段 | 跳跃与蹬墙组合可以流畅通过，回退与停顿会明显消耗距离 |
| 终点段 | 紧急提示不遮挡最后落脚点；终点、吞没与结算优先级正确 |

对候选参数记录：有效用时、每段进入/离开时的安全距离、全程最低距离、失败原因、暂停次数与时间、最大前进位置。必须保存两处代表性安全平台的暂停输入轨迹：停止移动 2 秒后能通过后续正常操作继续完成；站立持续等待最终被吞。两种测试中的停止移动都不使用 Esc。

#### 玩家循环与信号中继规则

选择关卡与模式 → 首次动作开始 → 建立安全余量 → 观察分支 → 选择稳妥路线或中继路线 → 接入中继争取喘息 → 分支汇合继续前进 → 成功或失败 → 快速重开并调整选择。

| 项目 | 批准的规则 |
| --- | --- |
| 激活方式 | 玩家身体接触节点，不增加按键 |
| 数量 | 新关卡2个可选节点，每节点每轮只能激活一次 |
| 初始收益 | 崩塌前沿暂停推进0.9秒，作为首轮调参值 |
| 玩家与计时 | 玩家继续正常跑跳，本轮用时继续累计 |
| 前沿 | 保持当前位置；延迟结束恢复固定推进，不后退、不传送、不按距离暗中变速 |
| 通关条件 | 不必收齐中继，存活抵达终点即可 |
| 计时模式 | 可记录激活数量，不产生追赶延迟 |
| 暂停和结果 | 暂停冻结延迟；失败或成功停止本轮；不能靠结算后接触继续激活 |
| 重开 | 重置节点、延迟、角色、镜头、计时和本轮激活统计 |

270×0.9=243单位是少推进的理论量。分支的实际收益还需扣除绕路及动作耗时：比较同一入口状态、同一汇合出口上的用时与安全距离。取得中继的额外耗时应明显小于0.9秒；若收益为负，先调整分支路径，再讨论延迟值。

边界补充：不同节点各提供一次完整延迟；极端情况下同帧接触两个不同节点可累计，两个节点最多贡献1.8秒，不因持续重叠刷新。激活发生在起步缓冲内时，缓冲仍按原规则消耗，中继延迟在其后消耗；有效delta分段处理，不重复消耗同一时间。已出现的死亡/吞没不能被中继撤销，失败优先于终点或奖励。具体同帧采集与判定顺序在A原型中冻结并记录。

计时模式一次自动死亡恢复仍属于同一轮，已激活节点不重复奖励/计数；R或再次挑战才创建新一轮。节点按稳定ID去重。最佳成绩改为按关卡与模式区分；原首关会话成绩映射到原首关，不与新关卡混写，仍不做长期存档。

#### 新关卡 断线中继站

新增一条约45–65秒的完整关卡。横向推进为主，两处局部分层分支在短段挑战后汇合。原首关继续保留。

| 段落 | 预计时长 | 内容与体验 |
| --- | --- | --- |
| 接入区 | 6–8秒 | 宽平台、低强度障碍，建立跑跳节奏，提前看见第一处中继 |
| 第一处分流 | 10–12秒 | 下层宽落点常规路线；上层两次高差跳跃取得中继，随后汇合 |
| 连续传输区 | 8–10秒 | 短跳、长跳和落地衔接，提供连续前进的顺畅段 |
| 第二处分流 | 12–16秒 | 稳妥路线落点更宽；中继路线使用一次蹬墙与空中落点组合 |
| 输出区 | 8–10秒 | 收束动作组合，终点提前可见，完成最后冲刺 |

五段预算合计44–56秒，整关45–65秒为含实际选择与操作差异的目标范围，不能当作已实测成绩。地图是段落和连接示意，世界尺寸以灰盒动作能力测试决定，不从参考截图或示意格数反推跳跃参数。

稳妥路线落点更宽、动作要求低，能够独立通关。中继路线需要更准确的起跳和衔接，收益位置及出口提前可见。选择后仍持续向前，不加入取完奖励再大幅回头的流程。两处分支的四种组合都应可达：稳/稳、中继/稳、稳/中继、中继/中继。

分别记录段落进入、离开、最低余量及分支入口/汇合点用时。采用普通方向与跳跃输入完成路线，不用传送、无敌或冻结追赶证明可达。定点fixture仅用于碰撞、状态或排版检查。

#### 核心体验与操作

自动奔跑 → 判断前方地形 → 跳跃或蹬墙 → 选择是否接入中继 → 继续前进并得分 → 失败结算 → 再次挑战。

无限模式自动向右奔跑，玩家专注起跳、跳跃高度、蹬墙与路线选择；保留短按低跳、长按高跳。蹬墙短暂反向弹出后恢复向右奔跑，不用强制水平位移覆盖墙跳。Esc暂停，R重开。原首关与断线中继站继续手动移动；无限模式是独立入口，不把旧计时挑战改成自动奔跑。

#### 模式规则

| 项目 | 批准的初版规则 |
| --- | --- |
| 终点 | 无终点，持续向前生成地图 |
| 开始 | 确认后自动奔跑，保留起步缓冲 |
| 失败 | 尖刺、坠落或被崩塌吞没，结束本轮；失败优先奖励，多候选只结算一次 |
| 中继 | 身体接触，每个稳定ID每轮一次；延迟追赶0.9秒并提供100分；角色与计时继续 |
| 暂停 | 冻结角色、计时、追赶、生成及表现；延迟不消耗 |
| R及同图重试 | 相同种子从起点开始，清理本轮所有状态 |
| 换图挑战 | 生成新种子并开始另一张地图 |
| 结算 | 总分、最远距离、中继数、用时、失败原因、地图种子与最高分 |

#### 随机地图与片段库

采用经过验证的地形片段加规则随机拼接。片段内部明确动作与落点，生成器选择片段、衔接、难度与奖励位置。首批12片段如下。

| 类型 | 数量 | 用途 |
| --- | --- | --- |
| 安全过渡段 | 2 | 起步、调整节奏及连接 |
| 单项障碍段 | 3 | 坑洞、尖刺、简单高差 |
| 连续跳跃段 | 3 | 不同起跳与落地节奏 |
| 中继分支段 | 2 | 稳路通过，或上路接入奖励 |
| 蹬墙组合段 | 2 | 复用墙面动作，形成较高难度 |

入口与出口采用统一接口，初版统一地面高度衔接，片段内部允许高差。接缝保留安全落脚空间；每段至少有一条实际验证的通路，中继分支另测。开局先安全与简单段，再加入复杂组合。相同片段不连续出现，高难段之间安排调整空间。危险提前进入视野，不能在角色脚下生成。候选无法满足连接条件时使用经过验证的安全过渡段兜底。

每个片段配置类型、稳定模板ID、入口/出口位置及可接受运动状态、碰撞/危险/节点数据、难度与选择权重；具体长度、接缝安全范围及可达界限在A/B测量后冻结，不从示意格数推导。地图设计模块展示片段池与选择关系，不代表一张已完成的固定地图。

同一构建版本、同一种子产生相同地形与节点序列；地形随机与装饰随机分开。改变装饰、帧率或预生成时机不能改变地形前缀。结算显示种子，便于同图重试和报告缺陷。

#### 计分与记录

总分＝距离分＋中继分。距离取起点以来最远前进值，每10个世界单位得1分；中继每次有效接入100分，时间只显示、不直接得分。距离12,000、中继3个时为1,200＋300＝1,500分。回退再前进不重复计分，同一节点不重复得分。

无限模式最高分独立保存到本机，退出后保留；原固定关的会话最佳规则保持。保存格式有版本，读取缺失或损坏文件应有明确默认处理，不污染固定关统计。同种子适合直接比较，不同随机种子仅用于个人最高分挑战；初版用统一奖励间隔和地形配比限制差异，不宣称联网竞技公平。

#### 追赶压力与难度

当前v0.3角色速度280、追赶270；长期顺畅奔跑会拉开距离，中继又增加余量。无限模式需单独设计压力曲线，固定关参数保持。

| 参数 | 初始候选与验证要求 |
| --- | --- |
| 自动奔跑速度 | 280，先复用现有动作参数 |
| 初始追赶速度 | 270 |
| 追赶增长 | 每30秒提高4，初测上限282 |
| 起步缓冲 | 2秒；初始后方距离先复用640，再按压力证据判断 |
| 中继奖励 | 0.9秒延迟及100分 |
| 中继间隔 | 约20–30秒路程，受生成与可达约束控制 |

以上均为原型比较值，不是已验证数值。难度时间使用有效游戏时间，暂停冻结，接入延迟时仍累计；奖励间隔依据生成路程预算，不能受停留或装饰随机影响。先起步宽落点及单项障碍，再连续跳跃与分支，最后加入蹬墙和较高组合比例；速度与密度都有上限。

错过中继后仍能继续尝试；扣除绕路成本后奖励有正收益；后期正确操作并接入中继应有维持余量的可能，不能到某时刻无论怎样操作都必死。用最不利允许奖励间隔和实测动作耗时核对长期收支，不能只比较0.9秒的理论收益。难度不靠随机不可达路线提高。

### 信号跑道 v0.5 立体跑酷与生命系统制作计划





2026-10-01，用户批准后制作人与主美已完成v0.5立体跑酷与生命系统源工程。六参数化结构、三点生命、无伤加速/伤害降速、安全恢复、追赶和规则版成绩、几何编辑器与美术反馈已实现；A至H八项任务按证据验收。实际参数调整、同版本独立操作、长局和局限见“信号跑道 v0.5 工程实现与验收记录”。原预算与里程碑日期保留为批准基线；本版不打包。

#### 版本目标与核心循环

玩家观察高低路线，跳跃前进并收集中继；无伤跑得越远，速度越快，操作压力和拉开追赶距离的机会同时增加。撞到危险或掉坑扣血并失去积累的速度，玩家依靠剩余生命重新组织路线。生命归零或被信号崩塌追上结束本局。

本版本验收关注三个结果：主路不再长期保持同一高度；高处路线有明确入口、奖励和出口；受伤后可以继续操作并重新加速。是否有趣需要实际试玩记录，结构检查和自动操作只能证明对应规则成立。

#### 制作范围与模式边界

新增规则用于正式无限模式及编辑器的无限试玩。保留现有跳跃高度、短按低跳、土狼时间、输入缓冲和墙跳基础参数；速度变化作用于自动跑的水平目标速度。固定关、计时关和旧实验入口沿用原规则，避免混淆历史动作验证。

本版制作三点生命、距离加速、伤害降速、掉坑恢复、立体地形、参数化几何、追赶联动、编辑器诊断以及对应视听反馈。回血、装备、滑行、战斗、新手教程和新主题场景留给后续版本。

#### 生命与伤害规则

每局初始化生命 3 点。尖刺等危险物每次有效接触扣 1 点，触发一次受伤事件，并将自动跑目标速度降回基础值。普通地面、平台、墙面碰撞不扣血。保持原有墙跳与滑墙规则。

有效伤害后进入 1.2 秒无敌期，这是初始调参值。持续接触同一危险物在无敌期内不重复扣血；多危险物在同一物理帧只结算一次伤害。无敌结束后仍停留在危险物内，需要重新检查接触，不能永久漏判。用闪烁、血量变化、短促音效和受伤提示反馈，避免长时间冻结输入或反向击退破坏自动跑。

生命归零立即结束本局。信号崩塌接触为终局事件，无敌期不能抵消它。同帧崩塌、致命伤害和奖励冲突时优先结算终局，只显示一张结果卡且不发放该帧奖励；非致命伤害帧先处理扣血与降速，再处理仍有效的节点接触。

掉坑判定仍由实际关卡流程触发，扣 1 点并降速；生命未归零时最多用 0.25 秒恢复到最近确认过的安全落脚点。安全点必须是已接触并稳定着地、可容纳角色、没有尖刺的实体表面，保留全局位置与所属片段，不使用跳跃途中位置。恢复后水平速度为基础跑速、垂直速度清零，清除上次运动扫掠和输入缓冲，防止跨地图误拾取。

掉坑恢复期间计时和追赶继续，前沿不回退。安全点若已被崩塌覆盖，结束原因为被追上；若原片段已回收，只能从当前仍存在且位于玩家原位置后方的已确认安全点选择，不能向前传送或无限循环恢复。极端情况下无有效安全点则明确结束为无法恢复。下沉地段必须高于坠落判定边界。

#### 距离加速与追赶联动

距离沿用当前界面的世界距离单位，不在本版本把它改称米。累计最高前进距离用于成绩。无伤加速距离使用自上次有效伤害后新增的最高前进距离，退回安全点再跑过旧路不增加加速距离或距离分。

初始调参公式为目标速度 = 280 + 100 × clamp(无伤新增距离 / 50000, 0, 1)，单位为世界单位每秒。即每新增 5000 距离增加 10，最高 380。曲线连续，实际水平速度按已有运动加速度接近目标；跳跃、墙跳、暂停不会直接抹掉无伤积累。伤害立即重置积累与目标速度，实际水平速度在最多 0.2 秒内降到基础区间，不改变当时的垂直速度。

追赶仍保留启动缓冲、随时间推进的阶段、中继延迟和基于安全距离的公开追赶补偿。初始联动方案将原基础曲线按当前跑速 / 280 缩放，并保留有界补偿；追赶提速连续，玩家受伤降速时追赶目标同步下调，在 0.5 秒内完成降速，前沿位置绝不瞬移。具体比例、补偿与阶段值由多速度试玩确定，不能仅以公式相近认定压力合适。

追赶验收覆盖基础、过渡与最高速度，分别观察主动收集中继、跳过中继和受伤降速的安全距离曲线。正常路线能拉开一定距离，跳过节点和失误会消耗安全距离；不能让最高速永久摆脱威胁，也不能让满血且有充足安全距离的玩家受一次伤就必然死亡。近距离失误被追上是预期风险。

#### 立体地图内容

新增六种结构，每种至少三个通过验证的几何变体；结构决定玩法关系，种子在允许范围内改变实际尺寸和位置。原有安全与中继结构继续可用，默认生成权重需要调整以减少重复平地。

| 阶梯抬升 | 地面连续抬高，逐级跳上后回落 | 主路需要跳跃；单级先使用 32 至 64 高差，不用高墙替代台阶 |

首轮保留片段 1280 长度、首尾至少 240 的安全连接区和统一段缝高度，让高低变化发生在片段内部。上下分路和抬升地段不要求整个地图一直向上爬。每个连续十段窗口除开局缓冲外至少包含三段明显高低变化，并且纯平安全段最多连续两段；约束冲突时用已验证的缓和起伏片段兜底，记录原因。

#### 参数化生成与生命周期

生成器输出最终几何快照，包含结构与变体、地面块、平台、危险物、唯一奖励、路线连接、安全表面和实际生成参数。预览、碰撞、绘制和恢复点都消费同一快照。几何随机数与视觉随机数分开，查看详情或切换预览不消费地形随机数。

在经过验证的范围和离散档位内采样平台高度、宽度、间距与位置；不能让用户输入任意值后声称保证可达。先计算保守连接范围，再进行真实物理验证。候选无解时尝试次数有上限，回退已验证结构并显示兜底次数，避免生成卡死。

同一构建、种子与配置必须生成一致的几何，不读取实时生命或即时速度决定尚未出现的地图。地图按基础到最高速度的整个包络验证，确保受伤后不会遇到原本只为高速生成的必死间隙。中继间隔、防连续高难、有限成本墙跳等原有约束继续生效。

#### 编辑器扩展与配置兼容

#### 已实现的玩法与地图

正式无限模式与隔离工具试玩使用三点生命，尖刺有效接触扣一点，1.2 秒无敌并降速；同帧多危险物去重，无敌结束仍重检持续接触。生命归零结束，信号崩塌不能被无敌抵消。同帧终局优先于奖励，并且只结算一次。

无伤新增最高距离将目标速度从 280 连续提高到 380，50000 距离封顶。伤害清除积累并将实际水平速度降到基础区间，保留垂直运动。回跑旧路不重复加速或得距离分；暂停冻结，重试初始化。

掉坑扣一点后在最多 0.25 秒内恢复到最近实际站稳的安全表面。时间与追赶继续，覆盖/回收/不存在的安全点不能用于向前传送或循环恢复。恢复清除运动扫掠与输入缓冲；安全点保存全局身份并随片段回收清理，长距离重定位保持距离与奖励身份。

六结构为阶梯抬升、下沉回升、断层桥接、连续平台链、上下双路线和高处接入回落。高差32/48/64、间距64/80/96组合生成真实几何，首尾统一安全地面。片段内部高低变化与上下路线有入口和出口，上平台允许从下方通过，下沉地面有垂直镜头跟随。

高路获得额外唯一节点，每个100分；两条路线汇合后的低节点都可接入。同一中继片段首次接入提供0.9秒追赶延迟，额外节点只继续加分，延迟预算随片段回收，避免安全距离无限增长。

追赶保留2秒启动缓冲、时间阶段和公开有界补偿，目标按当前跑速缩放，伤害后同步减速，前沿不瞬移。计分仍是最高距离除以10取整加唯一节点分。新规则最高分使用 signal_runway_endless_v05.json，旧文件保持；记录包含规则版、生成版、配置指纹和种子。

### 信号跑道 v0.6 跑酷节奏与风险收益制作计划





2026-10-01，制作人与主美两人完成用户批准的v0.6源工程。四类段落编排、高路三个有序节点及出口奖励、稀疏恢复站双路线互斥选择、得分明细、新版记录、节奏调参/定点试玩和正式表现已实现；A至G七任务按证据验收。实际规则、独立操作、继承证据和局限见“信号跑道 v0.6 工程实现与验收记录”。原预算与10月2至6日建议日期保留为批准基线，本版不打包。

#### 版本目标与核心循环

玩家观察下一段地形，选择稳定下路或高分高路。高路的连续节点形成明确挑战，成功完成获得额外分数；失误保留已得分，但中断当前连段并承担现有扣血、降速和追赶压力。经过恢复站时，玩家用路线选择补一点生命或领取额外分数，随后进入下一轮挑战。

本版希望验证三个体验判断：连续地图能看出挑战与缓和交替；高路值得冒险但下路仍有实际用途；补血能够帮助挽回一局，同时保留生命消耗和追赶压力。自动检查验证规则和可达性，实际操作记录用于评估这些体验。

#### 制作范围与继承规则

新增规则用于正式无限模式和编辑器隔离试玩。继承 v0.5 自动跑、跳跃与墙跳参数、280 至 380 无伤距离加速、伤害降速、三点生命、1.2 秒无敌、掉坑安全恢复、追赶启动与阶段补偿，以及每中继片段首次接入 0.9 秒延迟预算。固定关、计时关与历史实验入口保持各自规则。

本版制作段落节奏、距离难度安排、高路连段、恢复站、得分明细、生成编辑器扩展与对应视听反馈。教程、装备、角色养成、新主题场景和打包不在本次交付范围。

#### 地图段落与难度安排

段落是对一段或数段连续片段的玩法安排，内部继续使用参数化随机几何。地图先确定段落角色，再选择结构和已验证参数，预览和正式碰撞消费同一几何快照。

| 段落 | 玩家目标 | 地形与限制 |
| --- | --- | --- |
| 缓和段 | 调整状态并观察前路 | 宽落点、少量起伏，不能长期退化为重复平地 |
| 挑战段 | 连续跳跃通过组合地形 | 台阶、平台链与断层组合，具有可见起跳区与出口 |
| 分路段 | 决定稳妥前进或挑战高分 | 下路可稳定通过，高路有额外节点与连段入口，失误有落回下路的机会 |
| 恢复段 | 选择补血或继续冲分 | 安全连接区、两条短路线、互斥奖励，经过后汇回主路 |

先做单片段挑战灰盒，确有需要时才扩展跨片段组合。开局继承至少两片段安全缓冲。首轮限制挑战段最多连续两段，其后至少一个缓和段；恢复段前后使用安全连接，不能在选择出口放置落地尖刺。保留 v0.5 十段至少三段明显高低变化、纯平安全最多两连等约束；发生冲突时使用已验证缓和起伏段并记录原因。

按最高前进距离设置入门、进阶与持续挑战三档编排。首轮边界暂定 10000 和 30000 世界距离单位，挑战类段落的候选权重按 1、2、3 递增，上述连续上限始终有效。这是初始平衡方案，M1/M4 根据操作记录调整；难度不靠缩小至不可达的间隙。伤害后不让已生成地图突然降档，未来地图也不读取实时生命或当前跑速决定结构。

必经路线在 280、330、380 和空中受伤降速情况下均需真实物理验证。结构连接仍保留安全段缝与统一连接高度；从高路退出后能够继续前进。地图变化由种子、生成版本、冻结配置与片段索引确定，不能因预览、镜头或视觉效果消费随机数而改变。

#### 高路连段与奖励规则

高路挑战具有可见入口、三个按路线顺序排列的唯一挑战节点和明确出口。玩家经过高路入口后开始记录进度；普通中继节点与挑战节点需要有视觉区别。三个节点依次接入且到达高路出口后完成连段，初始额外奖励为 200 分，每个节点仍按现有规则获得 100 基础分。

进入下路继续前进、漏过必要节点、受到一次有效伤害或本局终止，均中断当前连段。高路允许的普通平台落脚不算中断；短暂无敌闪烁也不是新的中断事件。中断保留已获节点分，当前挑战不能通过回跑或掉坑恢复重新激活；没有进入高路的玩家不出现失败提示。

每个挑战保存全局唯一身份、入口、节点顺序、出口和下路退出区域。连段完成奖励最多结算一次，出段后清理活跃进度，回收和坐标重定位保留必要的防刷身份。连段奖励只加分，不增加额外追赶延迟；现有首次中继接入的延迟预算继续有效。

200 分是批准方案的初始数值。试玩比较主路和高路的基础分、额外分、受伤次数和失败原因后调整，避免额外收益小到不值得选择，或大到使下路失去用途。

#### 恢复站与互斥路线选择

首轮恢复站间隔在 16 至 24 个片段内按种子采样，第一站也遵循该范围，后续以相邻站之间的间隔计。生成位置不根据当前生命临时改动；恢复站使用安全连接并提前展示两条路线，在最高速度下至少提供约 1.2 秒的可辨认选择窗口，这一可见性需要镜头中的实际运行确认。

玩家通过其中一条路线的接入点作出选择：补血路线恢复一点生命，上限三点；积分路线初始奖励 200 分。积分数是制作时用于比较选择收益的初始调参值。补血不清除加速积累、不抵消崩塌，也不增加追赶延迟。两条路线都是短路线，完成后汇合，不暂停游戏或弹菜单。

满血时补血路线明确显示“生命已满”，积分路线继续显示实际分数；玩家仍可通行补血路线，但不额外获得生命或积分。接入任一路线就锁定该站，不能之后接入另一条领取第二份奖励。跨点扫掠意外同时命中时，按沿移动路径最早接触的入口决定，完全相同时使用固定优先级并记录诊断；布局应避免两入口同时可触及。

恢复站与挑战分别使用唯一身份。回跑、掉坑恢复、重复碰撞、暂停恢复和重定位不能重复补血或领分。非致命伤害与补血在同帧时先伤害并中断连段，再处理仍有效的站点；生命归零、崩塌接触或其他终局同帧时先结束，不能靠补血复活，也不发放该帧奖励。

#### 计分与局内记录

总分为最高距离除以 10 取整，加唯一节点基础分、已完成连段奖励和已选择恢复站的积分奖励。受伤不扣历史分；倒退不增加距离分。结算显示四类分数、完成连段数、补血站和积分站选择次数，帮助玩家理解本局路线收益。

规则升级后使用独立的 v0.6 最高分记录，保留 v0.5 和更早成绩。新记录携带玩法规则版本、生成版本、配置指纹与种子。坏档、写入失败、备份和原子保存继续按现有约定处理；编辑器试玩成绩隔离。R 使用同种子与本局冻结规则，换图或新局加载当前默认配置。

连续画布展示段落类别、阶段、挑战入口和有序节点、恢复站的两条路线与奖励、候选和兜底原因。新增挑战权重、连续上限、阶段边界、恢复站间隔与两类额外分数的草稿调参，非法值明确拒绝。调参有界，工具不会把任意自定义组合标为已经通过真实物理验证。

支持选中种子与指定片段附近直接隔离试玩，同时保留自然速度、三档速度、F9 受伤、F10 掉坑和 F8 返回。定点试玩明确标为调试入口，记录起始位置和注入状态，不能用其局长冒充正常开局。工具允许从挑战入口复验中断和出口奖励，从恢复站前复验互斥选择。
