#### 体验目标

操作响应明确，失误原因可读，重试成本低；首轮以一条45–90秒灰盒关卡检验手感与节奏。

#### 核心循环

1. 观察路线
2. 奔跑与跳跃通过障碍
3. 失败后快速重试
4. 抵达终点并查看成绩
5. 重玩挑战更短用时

#### 玩法规则

计时挑战模式（time_trial）：左右移动支持加减速与空中修正；跳跃高度随按键时长变化，允许短暂离地补跳和提前按键缓冲；贴墙可下滑并蹬墙跳。尖刺或坠落触发死亡，回到关卡起点。数值均为待试玩调整的参数，不以文档值判定趣味性。

- 胜利条件：玩家到达明确标识的终点区域，记录本次用时和死亡次数。
- 失败条件：触碰尖刺或坠出关卡边界触发单次失败，随即可重试；无永久失败。

- [ ] 真人试玩：至少3名未参与制作的玩家，记录误判和重试意愿

# 信号跑道 v0.5 立体跑酷与生命系统制作计划

2026-10-01，用户确认本版本方向：增加可跳跃的平台和起伏地面；角色随着无伤前进距离加速，受伤后降速；开局三点生命。团队为制作人与主美两人。本文件是已批准方向的制作基线，当前处于计划登记阶段，功能与体验尚待实现、验证。交付 Godot 源工程，不打包。

## 版本目标与核心循环

玩家观察高低路线，跳跃前进并收集中继；无伤跑得越远，速度越快，操作压力和拉开追赶距离的机会同时增加。撞到危险或掉坑扣血并失去积累的速度，玩家依靠剩余生命重新组织路线。生命归零或被信号崩塌追上结束本局。

本版本验收关注三个结果：主路不再长期保持同一高度；高处路线有明确入口、奖励和出口；受伤后可以继续操作并重新加速。是否有趣需要实际试玩记录，结构检查和自动操作只能证明对应规则成立。

## 制作范围与模式边界

新增规则用于正式无限模式及编辑器的无限试玩。保留现有跳跃高度、短按低跳、土狼时间、输入缓冲和墙跳基础参数；速度变化作用于自动跑的水平目标速度。固定关、计时关和旧实验入口沿用原规则，避免混淆历史动作验证。

本版制作三点生命、距离加速、伤害降速、掉坑恢复、立体地形、参数化几何、追赶联动、编辑器诊断以及对应视听反馈。回血、装备、滑行、战斗、新手教程和新主题场景留给后续版本。

## 生命与伤害规则

每局初始化生命 3 点。尖刺等危险物每次有效接触扣 1 点，触发一次受伤事件，并将自动跑目标速度降回基础值。普通地面、平台、墙面碰撞不扣血。保持原有墙跳与滑墙规则。

有效伤害后进入 1.2 秒无敌期，这是初始调参值。持续接触同一危险物在无敌期内不重复扣血；多危险物在同一物理帧只结算一次伤害。无敌结束后仍停留在危险物内，需要重新检查接触，不能永久漏判。用闪烁、血量变化、短促音效和受伤提示反馈，避免长时间冻结输入或反向击退破坏自动跑。

生命归零立即结束本局。信号崩塌接触为终局事件，无敌期不能抵消它。同帧崩塌、致命伤害和奖励冲突时优先结算终局，只显示一张结果卡且不发放该帧奖励；非致命伤害帧先处理扣血与降速，再处理仍有效的节点接触。

掉坑判定仍由实际关卡流程触发，扣 1 点并降速；生命未归零时最多用 0.25 秒恢复到最近确认过的安全落脚点。安全点必须是已接触并稳定着地、可容纳角色、没有尖刺的实体表面，保留全局位置与所属片段，不使用跳跃途中位置。恢复后水平速度为基础跑速、垂直速度清零，清除上次运动扫掠和输入缓冲，防止跨地图误拾取。

掉坑恢复期间计时和追赶继续，前沿不回退。安全点若已被崩塌覆盖，结束原因为被追上；若原片段已回收，只能从当前仍存在且位于玩家原位置后方的已确认安全点选择，不能向前传送或无限循环恢复。极端情况下无有效安全点则明确结束为无法恢复。下沉地段必须高于坠落判定边界。

## 距离加速与追赶联动

距离沿用当前界面的世界距离单位，不在本版本把它改称米。累计最高前进距离用于成绩。无伤加速距离使用自上次有效伤害后新增的最高前进距离，退回安全点再跑过旧路不增加加速距离或距离分。

初始调参公式为目标速度 = 280 + 100 × clamp(无伤新增距离 / 50000, 0, 1)，单位为世界单位每秒。即每新增 5000 距离增加 10，最高 380。曲线连续，实际水平速度按已有运动加速度接近目标；跳跃、墙跳、暂停不会直接抹掉无伤积累。伤害立即重置积累与目标速度，实际水平速度在最多 0.2 秒内降到基础区间，不改变当时的垂直速度。

追赶仍保留启动缓冲、随时间推进的阶段、中继延迟和基于安全距离的公开追赶补偿。初始联动方案将原基础曲线按当前跑速 / 280 缩放，并保留有界补偿；追赶提速连续，玩家受伤降速时追赶目标同步下调，在 0.5 秒内完成降速，前沿位置绝不瞬移。具体比例、补偿与阶段值由多速度试玩确定，不能仅以公式相近认定压力合适。

追赶验收覆盖基础、过渡与最高速度，分别观察主动收集中继、跳过中继和受伤降速的安全距离曲线。正常路线能拉开一定距离，跳过节点和失误会消耗安全距离；不能让最高速永久摆脱威胁，也不能让满血且有充足安全距离的玩家受一次伤就必然死亡。近距离失误被追上是预期风险。

## 立体地图内容

新增六种结构，每种至少三个通过验证的几何变体；结构决定玩法关系，种子在允许范围内改变实际尺寸和位置。原有安全与中继结构继续可用，默认生成权重需要调整以减少重复平地。

| 结构 | 空间设计 | 路线收益与约束 |
| --- | --- | --- |
| 阶梯抬升 | 地面连续抬高，逐级跳上后回落 | 主路需要跳跃；单级先使用 32 至 64 高差，不用高墙替代台阶 |
| 下沉回升 | 地面下降形成低洼，再分级爬回 | 坑底是可站立地面；出口可在基础速度通过 |
| 断层桥接 | 主路断开，由宽平台连接 | 明确起跳区与落地区，最长间隙不依赖高速才能通过 |
| 连续平台链 | 三至五个不同高度的平台 | 单次上升初始范围 32 至 64；总高度通过多次跳跃实现 |
| 上下双路线 | 低处稳定通路，高处跳跃链 | 上路至少多一个唯一节点，有提前可见的入口并在段尾汇回 |
| 高处接入回落 | 高平台中继后返回低层地面 | 落地区足够宽且无落地尖刺；不能成为没有出口的死路 |

平台不是散放的装饰。每条路线都定义入口、可站立表面、跳跃连接、奖励与出口。必经路线同时满足 280、330、380 三档速度，并覆盖起跳或空中受伤后的降速；可选上路失误应有机会落回下路，不能依靠扣血强行通过。改变高度与间距前先测现有角色的实际跳跃轨迹，不直接用理想抛物线作为通关证据。

首轮保留片段 1280 长度、首尾至少 240 的安全连接区和统一段缝高度，让高低变化发生在片段内部。上下分路和抬升地段不要求整个地图一直向上爬。每个连续十段窗口除开局缓冲外至少包含三段明显高低变化，并且纯平安全段最多连续两段；约束冲突时用已验证的缓和起伏片段兜底，记录原因。

## 参数化生成与生命周期

生成器输出最终几何快照，包含结构与变体、地面块、平台、危险物、唯一奖励、路线连接、安全表面和实际生成参数。预览、碰撞、绘制和恢复点都消费同一快照。几何随机数与视觉随机数分开，查看详情或切换预览不消费地形随机数。

在经过验证的范围和离散档位内采样平台高度、宽度、间距与位置；不能让用户输入任意值后声称保证可达。先计算保守连接范围，再进行真实物理验证。候选无解时尝试次数有上限，回退已验证结构并显示兜底次数，避免生成卡死。

同一构建、种子与配置必须生成一致的几何，不读取实时生命或即时速度决定尚未出现的地图。地图按基础到最高速度的整个包络验证，确保受伤后不会遇到原本只为高速生成的必死间隙。中继间隔、防连续高难、有限成本墙跳等原有约束继续生效。

流式回收继续保持有限活动片段；安全点索引随片段回收清理。坐标重定位同步处理角色、镜头、崩塌、地形和安全点，全局距离、加速进度、奖励身份不变。多层平台绘制与碰撞使用相同表面高度，装饰不制造误导性落脚点。

## 编辑器扩展与配置兼容

原编辑器增加结构/变体、平台高差与间距档位、上下路线与安全点的查看和调参。连续画布显示最终地面块和平台，详情区给出实际几何参数、兜底原因、路线连接与三档速度验证状态。可切换基础、过渡、最高速度试玩，并能模拟一次受伤或掉坑；明确区分估算、实际物理验证与尚未验证。

参数草稿沿用校验、稳定指纹、命名保存、比较、确认原子应用、备份恢复和 F8 返回。当前局使用冻结配置；普通新局加载新默认，R 保持同一配置与种子。编辑器试玩仍使用隔离成绩，不改正式最高分。

## 计分与记录

沿用距离分加唯一节点分的基本公式，高路收益来自额外节点，先不加入速度倍率。后退、恢复和重复触发不能刷距离分或奖励；受伤不扣已经获得的分数。

新生命与速度规则改变成绩条件，v0.5 使用独立的规则版本记录与最高分，旧版本成绩保留在原记录中。新记录携带种子、生成器版本、配置指纹与玩法规则版本；UI 明确显示当前规则下的最高分。坏档、写失败、原子保存与备份行为保留可见反馈。

## 风险与交付清单

最高速度增加落点偏差，降速减少空中水平位移；先测动作，再收紧平台参数。阶梯与平台侧面可能阻挡自动跑，要用真实碰撞检查。恢复位置可能落在崩塌之后，需明确终局；坐标重定位和片段回收不能留下失效安全点。增加高路奖励后可能压过下路收益，要用独立路线试玩记录比较。

交付包含主场景与编辑器源工程、新结构和配置、生命/加速/恢复/追赶实现、美术资源、旧配置适配、新规则记录、操作说明、实现与验收报告、冻结文件清单及 GameCreator 协作记录。当前登记的是未来 v0.5 计划，项目已交付版本仍为 v0.4.1；待 M4 通过后更新正式版本并上传已授权的 GitHub 仓库。

- 胜利条件：单局无终点，以当前规则版最高分为目标。
- 失败条件：生命归零、信号崩塌追上，或掉坑且无有效恢复点；按优先级只结算一次。
