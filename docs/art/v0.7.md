## 视觉方向

沿用工业信号场景：深蓝金属体块、白色可站立顶沿、青色角色与生命、金色收益路线、珊瑚色危险，以及滚动信号波。新增空间层次让坡地、架空平台、断桥和下沉回升在运动中容易识别。保持现有角色、背景、状态栏、三点生命、连段与恢复站语言。

可站立顶沿随实际地形轮廓连续变化，坡面不会被水平装饰线覆盖。高路的支撑和连接跟随真实几何；通过入口、延续和汇回的小标识表达路线，不用亮色长线跨过实际空隙。曲线崩塌保持，旧版直线前沿不作为本版视觉元素。

| 信息 | 色彩与形状 | 放置规则 |
| --- | --- | --- |
| 实际落脚面 | 白色顶沿，由正式地形绘制提供 | 对应真实地面段/平台/坡面，不重复绘制第二套边界 |
| 地形侧面与支撑 | 深蓝灰金属面、暗斜撑、短铆钉 | 贴合实际实体下方，明显弱于顶沿与角色 |
| 主路方向 | 灰青短箭头，必要时“主路” | 接近实际分岔或汇合；背景稀疏，避免每段重复大标题 |
| 高路入口/延续/汇回 | 金色短箭头，分别“高路入口”“高路延续”“汇回主路” | 由 routes/connection 的真实连接决定，延续标记不冒充奖励 |
| 连段奖励 | 原六边序号1/2/3、出口实际分数 | 来自真实 challenge/节点/事件，与普通路线方向标记区别 |
| 恢复站选择 | 青色医疗十字、金色积分菱形、选择/锁定状态 | 沿用两路互斥信息，实际收益来自事件 |

色板复用：背景 `#0E1824/#18212B`，主文字 `#E6EFED`，次级 `#9BB5BA`，青色 `#45DCCB`，金色 `#FFD166`，危险 `#FF685C`。结构类别通过轮廓、支撑形式和短文字区别，灰度不依赖颜色猜路线。

## 四类空间结构

| 结构 | 表现安排 | 路线读取重点 |
| --- | --- | --- |
| 坡地连跳 | 金属侧面沿真实斜面裁切，稀疏短斜撑随高低调整；坡底轻暗层区别于远景 | 先看坡向和前方真实落点，不把表面纹理画成台阶 |
| 高台跨越 | 高台垂直侧壁、平台下方短梁和暗支撑，金色入口牌只在真实上路入口 | 区分高台顶面、起跳边与下一落点，保留空中运动轮廓 |
| 断桥接续 | 实际桥段下方桁架与端部短结构件，各桥段之间保持空白 | 明确断口、平台间隔和接续方向，不用装饰梁把断口填成可走面 |
| 下沉回升 | 下沉实体侧面较深，背景管线减少，回升坡面用同一实体语言 | 清楚下方可落脚地面和前方回升方向，镜头下移时提示仍可读 |

`zone` 用于空间层次和装饰密度，不赋予额外难度、奖励或危险含义。`spatial_id` 决定结构表现，不依旧 template_id 推断实际形状。v0.6 已出现模板身份保留而几何改变的连接，v0.7 必须仅读最终快照。

跨2至3片段高路连续处采用同一短标识语言，接缝不会多加一根明亮竖线。正常落地不表现为连段中断；没有新奖励事件的路线延续不加数字、不播接入声、不显示额外分数。确有汇回出口时才显示汇回标识。

## 待放行接口与坐标契约

下列字段来自制作计划；具体元素结构、字段类型和值以 A/B 放行文档及真实快照为准，本文不宣称它们已经实现。

| 只读数据 | 主美用途 | 放行时需核对 |
| --- | --- | --- |
| geometry.ground_segments | 坡面走势、侧面/支撑锚点 | 元素端点结构、是否包含平面段、空隙是否显式分段 |
| geometry.polygons | 实际实体内部的金属侧面和纹理边界 | 每个多边形的坐标/绕序与碰撞归属；平台是否单独表示 |
| geometry.routes | 主路/高路入口、延续、落脚与汇回 | 路线 kind、点列或表面引用、跨段路线身份与真实入口/出口 |
| geometry.jump_windows | 避让起跳与落地区域，辅助检查路线标牌位置 | 起跳/落点的几何类型、所属路线/速度档、是否为调试信息 |
| geometry.connection | 实际片段入出高度和高路接缝 | 前后连接身份、端点、续接/开始/结束状态；不存在连接的表达 |
| geometry.spatial_id / zone | 四结构选择及空间装饰密度 | 合法枚举、缓和/恢复段默认值、兜底快照类型 |
| chunk.id / origin / course.total_offset | 回收、位置与稳定装饰身份 | 几何坐标为片段局部；origin为重定位后的运行局部；全局身份不随位移改变 |
| challenge / station / route事件 | 复用现有真实进度和选择表现 | 节点随坡面/高路实际位置，跨段挑战的事件身份与出口归属 |

不由美术重采样随机数、重新生成坡形或计算可达性。跳跃窗口用于布局避让与测试观察；正式画面不默认绘制调试框或整条预测轨迹。未提供或不适用的新字段不猜补几何。旧配置2/3/4与固定模式保持现有表现。

拟定 `spatial_visual.gd` 使用 identity world transform，提供 `bind_flow(flow, course)`；读当前活动 chunks，监听既有 `chunks_changed/world_shifted`，通过同一全局身份更新绘制，不保存无限历史。拟提供只读 `presentation_state()` 用于核对活动身份、计时与可见标识；若制作人已有不同标准，以放行接口为准。

暂停冻结装饰时钟，菜单/终局停止动画，新局重新绑定并清理旧身份，退出断开信号。支撑优先在地形/玩家后方；世界提示层次须与正式地形 z/order 核对后确定，不能用低 z 但错误轮廓制造假地形。viewport外装饰裁剪，数量随活动片段有界。

## 屏幕布局与高速可读性

逻辑画布沿用960×540，检查实际1280×720与960×540。已有生命条(24,450)380×60、连段条(420,450)280×60，工具提示在右下；既有HUD与窗口边界必须读取真实 Control Rect 核对，不只看文字字段。

所有世界标签位置跟随实际表面，不能沿用统一固定 y330/y349 的出口文字来覆盖高低变化后的落点。在附近实体、奖励节点及相机画面共同约束下安排短牌；没有清楚位置时省去次要装饰文字，保留真实落脚边沿、节点和必要方向信息。主美范围不能移动业务 HUD，若HUD盖住必经坡面/落点则报告制作人调整镜头/接线。

坡地、下沉、高架镜头下重点检查：白顶沿完整、断口空白、起跳边/落点可辨、支撑弱于实体轮廓、跨段高路方向一致、站点预告与生命/连段/工具提示不相交。高速380的实际预告窗口与读取时间在正式E测量，当前不预先承诺秒数。静态两尺寸与灰度图用于布局判断，不替代运动和碰撞检查。
